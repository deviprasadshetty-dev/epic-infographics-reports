01 — Verdict on the claim

"On par with Opus 5 and GPT 5.6": partly true, not universally

The claim circulating online needs a scope correction. Against official vendor-reported numbers, V4.1 Flash beats or ties both rivals on short, high-volume agent loops — and loses clearly everywhere else.

  • TRUE — short-horizon agentic coding (5 wins): DeepSWE v1.1 74.2 vs Opus 74.0 / Sol 73.0; Terminal-Bench 2.1 90.6 vs 89.1 / 88.8; AutomationBench 54.8 vs 50.3 / 45.8; Agent's Last Exam 31.8 vs 28.6 / 26.7; CyberGym 88.1 vs Sol 84.5 (Opus not reported). HLE with tools 63.9 vs Opus 63.6 is effectively a tie.
  • FALSE — long-horizon, security, pure knowledge: Opus leads Terminal-Bench 3.0 (43.3 vs 30.0), 4.0 (51.8 vs 31.2), ProgramBench (37.0 vs 20.3), NL2Repo (75.3 vs 64.0). Sol leads SEC-Bench Pro (74.3 vs 62.8), ExploitGym (33.7 vs 15.3), GPQA Diamond (94.1 vs 90.9). Opus leads text-only HLE 56.3 vs 36.8–39.1 by a wide margin.
  • TRUE — cost and speed: peak $0.30 input / $1.20 output per 1M tokens, off-peak half that; roughly 4x cheaper than V4 Pro it replaces and ~17x cheaper on input / ~21–42x on output than Claude Opus 5 ($5/$25) and GPT-5.6 Sol ($4–5/$20–30). Lab-measured throughput is 206 tok/s (Artificial Analysis) with OpenRouter's best provider at 119 tok/s; community reports reach 300–400+ tok/s. Concurrency limit rises 500 → 2,500.
  • Caveat — vendor harness, tiny margins: all head-to-head figures come from DeepSeek's own harness at maximum reasoning effort (reasoning_effort=100, temp 1.0, top_p 0.95), and most wins are by 0.2–4.5 points — within harness noise. First independent data is now in: Artificial Analysis scores it 40 on the Intelligence Index (well above the open-weight-large median of 18) at a lab-measured 206 tok/s, but flags it as very verbose (250M eval tokens vs 130M median). Treat vendor decimals as provisional until more third parties re-run.
  • Practical rule: route bulk agent traffic to V4.1 Flash; keep a frontier model for the hard ~5% — marathon sessions, repo-scale refactors, offensive security. DeepSeek itself signals this by keeping a bigger V4.1 Pro for later.
Do not trust bare benchmark screenshots. Every comparison table in this report states its source. Vendor-run rows are marked as such; community praise is marked as anecdotal. Anything that failed live verification was cut.

02 — What the model is

Specs (official, live-verified)

V4.1 Flash is the smallest model in a new architecture family — "Flash" refers to active compute per token, not total size. Total weights are large; per-token cost is small.

Architecture

Causal Encoder–Decoder MoE
  • 552B backbone params
  • 8B active / prefill · 16B active / decode
  • 40-layer 20 enc + 20 dec
  • 1 shared + 384 routed experts 6 active / token
  • 196B Engram conditional memory

Efficiency tech

Why it is cheap to serve
  • 890 bytes KV cache / token (~1/4 of V4 Flash)
  • 1/8 SSD KV footprint (SWA Bounded Replay)
  • CSA2 sparse attention + FP4 E2M1 KV
  • DSpark speculative decoding
  • reasoning_effort 1–100, controllable

Context & I/O

API model id: deepseek-flash
  • 1M input context
  • 384K max output
  • text + image in · text out, native vision
  • tool calls · JSON · Responses API supported
  • MIT license open weights on Hugging Face
Training: from scratch on 45T multimodal tokens, context extended to 1M at the 34T mark. Post-training is standard SFT → RL → on-policy distillation; DeepSeek credits gains to large-scale synthetic agent-task generation, not a new algorithm. Sampling for reported scores: temperature 1.0, top_p 0.95, max reasoning effort.
Lifecycle note (verified on pricing page): V4 Flash and V4 Flash Vision Exp are retired and temporarily route to V4.1 Flash. V4 Pro was to route to V4.1 Flash from 04:00 UTC 14 Sept 2026 — but the pricing page now carries a footnote that V4 Pro API service continues after Sept 14 unchanged "in response to user demand." One community report of being billed Pro rates while expecting Flash routing is consistent with this last-minute change. Pin model id deepseek-flash rather than assuming Pro auto-routes.

05 — Real limitations

Where it falls short

  • Long-horizon autonomy gap: ~13–20 points behind Opus on Terminal-Bench 3.0/4.0. Marathon sessions and repo-scale refactors still favour Opus.
  • Security gap: ~11 points behind Sol on SEC-Bench Pro, ~18 behind on ExploitGym. Do not pick it as a security specialist.
  • Pure knowledge/reasoning gap: text-only HLE ~17–20 points behind Opus; GPQA ~3 points behind Sol. Tool use closes the gap; without tools it is not frontier.
  • "Flash" does not mean small to host: 552B total (some HF listings show ~485B loadable — the delta is the Engram memory block). Budget ~175GB at 4-bit / ~220GB at 5-bit plus offload; KV is tiny (~900MB at 1M context) but weights are not. NVIDIA DGX Spark owners confirm 500GB+ official weights cannot fit 4x512GB unified memory as-is; workable configs need tensor-parallel 3–4 plus NVMe Engram offload (one user reports 369 tok/s over 27,700 steps with TP=4). One local user quipped it is "Flash Max, not Flash."
  • Scores need max reasoning effort: all headline numbers use reasoning_effort=100, the most expensive setting. Lower effort = lower accuracy; advertised cheapness assumes you also tune effort down, which surrenders the benchmark edge.
  • Very verbose — output tokens are the bill: Artificial Analysis measured 250M eval tokens vs a 130M median, nearly double. At $1.20/M output (peak), verbosity eats into the input-price advantage on reasoning-heavy tasks ($0.27/task, $476.89 total eval cost). One HN user notes output on high effort runs ~2x a rival's medium setting.
  • Known agent bugs (community-reported, unverified): infinite loops, hallucinations, premature termination, invalid tool calls that derail agents into retry loops; occasional Chinese-language thinking chains/answers to English prompts; web UI reportedly lost PDF reading; LM Studio tensor-format load failure; uneven OpenRouter latency. Expect rough edges on a two-day-old release.

06 — What real users say

Community reception (anecdotal, labelled)

First-48-hour reactions from Reddit, Hacker News, and hardware forums. Anecdotes, not measurements — useful for direction, not proof.

  • Speed praise is unanimous: "300–400 tok/s", "blazing fast", "killed the demand in one shot" (research proposal vs GPT Astra). Direction matches the lab-measured 206 tok/s (Artificial Analysis) — fast either way.
  • Launch thread heat: Hacker News launch discussion drew ~417 points / 218 comments in its first day, centred on KV-cache compression tech and price-per-task rather than benchmark triumphalism. Top sentiments: "how much power you get for the cost" (full Rails app + tests), agents at "20–30% of the price per task", and "the price drop is more interesting than the benchmark improvement."
  • Naming backlash: multiple r/LocalLLaMA users dispute "Flash" for a 485–552B model (vs 304B for Flash 0731, 1.7T for Pro): "You can't inflate the model by 50% and call it a flash." Counter-argument: "flash" now means active-compute-per-token, and the label scales with lab compute.
  • Self-hosting pain: "doesn't fit dual DGX Sparks", "even with 4x DGX Spark we can hardly run this locally." Workable quants discussed: ~4-bit ≈ 175GB, 5-bit ≈ 220GB, NVFP4 + Engram offload on 256GB boxes. Not a laptop model.
  • Benchmark sceptics exist: "those stats are inflated, no way it's competing against GPT SOL and Opus" — a fair reflection of the vendor-run caveat above. Others note open weights historically trail closed frontier by months and expect V4.1 Pro, not Flash, to be the true frontier fight.
  • Billing confusion (actionable): one user spent two off-peak hours on Pro expecting Flash routing/pricing and was billed Pro rates — consistent with DeepSeek's late footnote keeping Pro alive. Verify your model id and invoice before running bulk jobs.
